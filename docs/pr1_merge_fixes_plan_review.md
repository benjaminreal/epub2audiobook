# PR #1 merge-fix plan review

**Decision:** Keep the three fixes and the stated privacy boundary. The plan matches the current defects in `cli.py` and `tts_engine.py`; tighten the output-path semantics and error-boundary coverage, and trim unrelated regression tests before implementation.

1. **Clarify existing-directory semantics and keep one output preflight — Required.** `_resolve_output_path` currently treats any existing directory as an output directory before checking its suffix. That preserves directory arguments, including a directory named with `.m4b`, but conflicts with the plan's instruction to reject an output directory “masquerading as a file.” Preserve the current directory-first rule unless there is evidence that `.m4b` directories must become errors; state the rule and test it. Continue validating the resolved destination before `create_tts_engine`, and ensure the default branch is covered. This keeps the existing interface while preventing an actual file destination from reaching TTS with an unusable parent or target.

2. **Include late `OSError` paths in the promised exit-code handling — Required.** The CLI currently catches `AssemblyError` and `DependencyError`, while `assemble_audiobook` can raise `OSError` from parent creation or process launch. The success summary also calls `output_path.stat()` after the assembly handler. Catch filesystem failures at the relevant assembly/output boundary and return code 3 without a traceback; keep the catch narrow and do not turn unrelated programming errors into processing errors. The planned mocked late-failure test should specifically inject `OSError` and assert the exit code and safe diagnostic.

3. **Scope Kokoro suppression to the actual logger and test its direct output — Required.** The installed Kokoro 0.6.1 package uses the `kokoro_onnx` logger, attaches its own stdout handler, and emits phonemes at DEBUG. Suppression must cover Kokoro construction and `create()` calls, and restore the logger's prior level/state in `finally` after both success and failure. Tests should set the logger to DEBUG directly, inject a distinct phoneme marker into a debug record, and assert it is absent from captured stdout as well as application stderr/error strings. Keep the existing tests for backend `RuntimeError`, content-bearing `TTSError`, and initialization failures; no real model or download is needed.

4. **Keep exception sanitization at the public TTS boundary — Required.** The current base `generate()` embeds both the first 100 text characters and the backend exception string, while Kokoro/Piper initialization errors preserve backend text and chained tracebacks. Sanitize both ordinary exceptions and already-raised `TTSError`s; retain safe stage/type and chapter-index context. The marker tests should cover the final CLI warning and skipped-chapter summary as well as exception strings, since the same error is printed again at the end. Preserve the documented limit: this protects supported application diagnostics, not arbitrary native-library output or metadata/path privacy.

5. **Use one temporary-directory lifetime and test unwinding — Required.** A context-managed `TemporaryDirectory` is sufficient for success, all-TTS failure, assembly failure, and a propagating `KeyboardInterrupt`; it also avoids leaving cleanup split between return paths. Assert generated chapter files disappear and an unrelated sentinel remains. Do not test or claim cleanup after forced process termination. Updating only the two contradictory `CLAUDE.md` statements is appropriate; the v1 release definition's later stable resume workspace remains a separate future feature.

6. **Trim tests unrelated to these fixes; keep packaging/security work out — Required for minimal scope.** The proposed paragraph extraction, chunking, scene-break, and sample-rate checks exercise unchanged TTS behavior and add unrelated coverage to a new suite. Drop those checks here. Keep the path, content-marker/logger, cleanup, and late-failure tests. A synthetic WAV-to-M4B smoke test is useful but optional; if retained, skip cleanly when `ffprobe` is absent and do not make it a new dependency. Patch the default output directory to a test temp directory so path-probe tests never touch the user's Downloads folder. Permission tests should not rely only on chmod bits, which may not fail under a privileged runner; inject a `PermissionError` at the filesystem operation when needed.

7. **Simplify execution ownership if convenient — Optional.** The two implementation workers both touch `cli.py`, and the separate test worker adds another handoff. One implementation owner can make the scoped changes across CLI, TTS, assembler error handling, and the small documentation edit, followed by the parent's diff review and the same targeted test run. Keep the existing sequential split only if it materially reduces edit conflicts; it does not change the technical acceptance criteria.

The `ruff` comparison, `git diff --check`, protected-file hash check, no-download/no-inference constraint, and no-commit/push/merge boundary are proportionate and should remain. No need to expand this work into model download integrity/timeouts, parser repair, broad lint cleanup, resume/atomic-output machinery, or history/privacy cleanup.
